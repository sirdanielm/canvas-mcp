# Goals, methods and current work

The aim is dependable grading support that saves teacher time while preserving
original evidence, exact identity, academic policy and teacher control. This page
owns the current agenda. Procedures belong in the linked guides; detailed case
history, approvals, installed pins and readback receipts remain private.

## Priorities

The current scoped work order determines priority, including any repository-only
work. For authorized grading, the aim is teacher-ready score/feedback proposals.
Use retained evidence and existing domain engines; resolve actual source/policy
holds and prepare reviewable score/feedback pairs before expanding infrastructure.
Execution and delivery use the current work order's authorization and their
respective academic/tool checks; routine stage transitions do not need duplicate
project approval.

For the Unit 2 handback, batch work by stage: admit exact source packets,
retain literal readings, apply the issued form and sealed policy, then check
score and full-feedback proposals. Resume each batch at its first unfinished
stage and reuse valid saved work. Keep review familiar and inspectable in the
existing Sheet/workbench while reusing the installed local engines. Qualifying
an optional front end is separate work. Consider a backend change only when an
observed workflow need warrants it. Teacher acceptance and delivery remain
separate gates.

1. Reuse valid saved evidence and results to produce useful proposals without
   repeating paid analysis or reconstructing work from chat history.
2. Preserve two intake lanes: Canvas submissions and teacher-folder/paper
   evidence. Bind each result to its actual source, assignment, form and attempt.
3. Keep protected GET observations, teacher-owned EDIT values and original
   baselines intact through refresh, review and separately authorized delivery.
4. Show purpose, owner, evidence, decision, hold, next action and completion proof
   in the existing workbench. Resolve known blockers before adding infrastructure.

## Grading flow

Both intake lanes retain their original bytes and provenance. Reuse an existing
result only when its source, policy, identity and substantive revision still
match. A paper reassessment label never supplies a Canvas attempt number.

| Work | Review and staging method | Final delivery |
| --- | --- | --- |
| Formative participation | Canvas or paper/folder intake → source-bound participation proposal and private analysis → local QC/review → UNAPPROVED central EDIT draft | Fresh Canvas comparison, exact teacher approval and separately gated **score-only** publication |
| Summative results | Canvas or paper/folder intake → literal reading → policy-bound scoring and full itemized feedback → the qualified accepted-decision or unapproved-proposal EDIT route | Separate score and full-feedback permissions, transport histories and independent readback |

An ordinary draft may be staged before final teacher approval. It remains
UNAPPROVED and supplies no Canvas publication authority. Participation analysis
and local provenance notes are private; they are not student comments. Accepted
test scores and full feedback derive from the same reviewed result and retain
separate delivery evidence. Missing source or identity is a hold, never a zero.

Retain supported readable feedback privately when a whole numeric total remains
held. Do not coerce that hold into a numeric accepted-pair transfer. Feedback-only
EDIT staging needs its own qualified route; its existence is not implied by a
formatter, version label or the generic accepted-result bridge.

## Evidence and recovery

Quarantine held source/identity/attempt cases and continue independent eligible
work. Preserve an uncertain operation's target locks and reconcile that same
history; a held case blocks only its affected targets or genuinely shared
resource. Within an authorized bounded task, eligible Sheet projection and
ordinary UNAPPROVED EDIT drafts do not need a new project confirmation merely to
advance a stage. Teacher acceptance, mandatory tool confirmations and the
current paid/publication limits remain effective.

Retain separate evidence for source revision, installed owner/pin, real-case
qualification, teacher decision, EDIT readback, score outcome and comment
outcome. A dated case qualification covers its bound case, not current service
liveness or a rollout. The sole EDIT owner reconciles locks and original history
before another send, preserving manual Student Info fields, catalog names,
teacher notes, accepted results and completed transfers.

Use the [documentation map](documentation-map.md) to select a procedure and
[repository maintenance](repository-maintenance.md) before source or checkout
changes. Retain failed reads, original baselines, higher existing grades, custom
notes and unresolved operations. A current absent comment does not prove a
historical append was never sent; reconcile its original history.

Earlier delivery counts and source qualifications remain dated evidence in the
[previous guide](https://github.com/sirdanielm/canvas-mcp/blob/16b06b5151c3595b043cb300e963b7de448ca738/docs/goals-and-status.md)
and private owner receipts. They are not current queue counts, service health or
permission to resume. Public guidance contains no student identities, source
links, credentials or private receipt contents.
